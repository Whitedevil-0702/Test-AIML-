# AI/ML Learning Path

A beginner-first, GitHub-native AI/ML course for teammates who may be starting with no prior AI, machine learning, or mathematics background.

> **Course principle:** Learn → Understand → Build → Submit & Review → Demonstrate Mastery.

This repository adapts the strongest patterns identified in the `Courses-And-FrameWorks` repository report: resource-guided learning, practical challenges that increase in difficulty, individual work evidence, Markdown documentation, and branch/pull-request review. It adds explicit prerequisites, resource mapping, rubrics, and completion criteria.

## Start here

1. Read [`COURSE_FRAMEWORK.md`](COURSE_FRAMEWORK.md).
2. Follow [`LEARNING_PATHS.md`](LEARNING_PATHS.md) in order.
3. Use [`RESOURCE_INDEX.md`](RESOURCE_INDEX.md) to open the supplied resources.
4. Start Module 01 and maintain your own copy of [`Members/PROGRESS_TEMPLATE.md`](Members/PROGRESS_TEMPLATE.md).
5. Submit work using [`CONTRIBUTING.md`](CONTRIBUTING.md) and the assessment template in `Shared-Templates/`.

## Course at a glance

| Stage | Module | Main outcome |
|---|---|---|
| 0 | AI and computational thinking | Explain AI, ML, deep learning, and generative AI in your own words |
| 1 | Python foundations | Write small Python programs and explain the code |
| 2 | Data and mathematics | Inspect, clean, summarize, and visualize a dataset |
| 3 | Core machine learning | Train and evaluate baseline regression/classification models |
| 4 | Model improvement and responsible ML | Compare models, inspect errors, and communicate limitations |
| 5 | Deep learning and neural networks | Understand the neural-network learning loop and run a guided experiment |
| 6 | Generative AI and LLMs | Explain LLM basics and build a small, clearly scoped GenAI prototype |
| 7 | AI application and capstone | Present a documented end-to-end project |

The supplied resources strongly support introductory AI/ML and core ML. Deep learning, LLM engineering, RAG, and deployment are included as **later proposed modules**; their full resource coverage must be expanded before those modules can be considered complete.

## Repository map

- `AI-01-Introduction-to-AI/` — first principles, terminology, AI vs ML, and problem framing.
- `AI-02-Python-and-Data/` — Python readiness, data handling, and essential mathematics.
- `AI-03-Machine-Learning/` — ML workflow, supervised/unsupervised learning, evaluation.
- `AI-04-Deep-Learning/` — neural networks and a guided first experiment.
- `AI-05-Generative-AI-and-LLMs/` — GenAI, LLMs, prompting, and RAG concepts.
- `AI-06-AI-Project-Development/` — application design, evaluation, deployment considerations, capstone.
- `Shared-Templates/` — reusable lesson, assessment, and review templates.
- `Members/` — progress-record template.
- `docs/` — design rationale, coverage, and verification notes.

## How completion works

Watching a video or opening a page is not proof of mastery. Each module asks learners to explain concepts, complete a practical task, document their work, and receive a review. Suggested passing score: **70/100**, plus demonstrated correctness for the practical component. This is a proposed team policy, not an existing rule from the reference repository.

## Important source and coverage notes

- The provided resource links are recorded in `RESOURCE_INDEX.md`.
- The YouTube URL supplied by the team is preserved. Its title and timestamps are not asserted because they were not independently verified during creation.
- Resource links are external and may change. The course provides original exercises and explanations rather than reproducing third-party lessons.
- This is a local repository package. It has **not** been published to GitHub.

## Suggested first-week plan

- Session 1: Module 01 lessons 01–02; explain AI vs ML vs deep learning.
- Session 2: Python readiness check; complete the small Python exercise.
- Session 3: Review one ML resource and draw the ML workflow.
- Session 4: Pair discussion: choose a problem, identify data and target, discuss risks.
- Session 5: Submit the first mini-assignment and request peer review.

Adjust the pace to the team's availability; the sequence matters more than the calendar.
